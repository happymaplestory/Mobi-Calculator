# 마비노기 모바일 계산기

## 1. 프로젝트 개요

이 프로젝트의 목표는 **마비노기 모바일 계산기** 웹사이트를 만드는 것이다.

사용자가 게임에서 확인한 데이터를 웹페이지에 입력하면 JavaScript가 해당 데이터를 바탕으로 필요한 계산을 수행하고 결과를 화면에 표시한다.

구체적인 계산 항목, 입력 항목, 계산 공식 및 화면 구성은 추후 요구사항에 따라 정의한다.

현재 정의되지 않은 내용은 임의로 확정하지 않는다.

## 2. 운영 환경

- GitHub Repository에서 모든 소스코드를 관리한다.
- GitHub Pages를 이용하여 웹사이트를 외부에 공개하는 것을 기본으로 한다.
- 정적 웹사이트를 기본 구조로 한다.
- HTML, CSS, JavaScript를 사용한다.
- PHP는 사용하지 않는다.
- 별도의 웹 애플리케이션 서버를 운영하지 않는다.
- 별도의 데이터베이스 서버를 사용하지 않는다.
- 별도의 유료 서비스 사용 없이 운영하는 것을 목표로 한다.

## 3. 사용자 데이터 처리

사이트는 사용자 계정을 관리하지 않는다.

다음 기능은 기본적으로 사용하지 않는다.

- 회원가입
- 로그인
- ID / Password
- 관리자 계정
- 사용자별 서버 데이터 저장
- 개인정보 수집

사용자가 입력한 게임 데이터는 서버 또는 데이터베이스에 저장하지 않는다.

## 4. JSON 데이터 파일

사용자가 입력한 게임 데이터를 JSON 파일로 저장하고 다시 불러올 수 있어야 한다.

### 저장

사용자가 입력한 데이터를 JavaScript로 JSON 형식으로 변환하여 사용자의 PC에 파일로 다운로드할 수 있도록 한다.

### 불러오기

사용자가 저장해 둔 JSON 파일을 웹페이지에서 선택하면 JavaScript가 파일을 읽고 기존 입력 데이터를 복원할 수 있도록 한다.

기본적인 데이터 흐름은 다음과 같다.

사용자 입력
→ JavaScript
→ JSON 생성
→ 사용자 PC에 다운로드

JSON 파일
→ 웹페이지에서 불러오기
→ JavaScript로 읽기
→ 입력값 복원
→ 계산 수행

## 5. 계산 기능

웹페이지에서 사용자가 입력한 마비노기 모바일 게임 데이터를 이용하여 계산을 수행한다.

계산은 기본적으로 사용자의 브라우저에서 JavaScript로 처리한다.

계산 결과는 웹페이지에 표시한다.

구체적인 계산 대상과 공식은 향후 별도의 요구사항으로 정의한다.

## 6. 사용자 환경 및 UI

웹사이트는 모바일 환경과 PC 환경을 모두 지원한다.

사용자의 환경에 따라 단순히 화면 비율만 변경하는 것이 아니라, 화면 크기와 기기 환경 등을 고려하여 적절한 UI를 제공한다.

- 모바일 환경에서는 모바일 화면에 적합한 UI를 제공한다.
- PC 환경에서는 넓은 화면에 적합한 UI를 제공한다.
- 모바일과 PC 환경의 특성에 따라 글자 크기, 입력 요소, 버튼, 여백, 배치 등 UI 크기와 표시 방식을 적절하게 조정한다.
- 화면 크기에 따른 반응형 UI를 적용한다.
- 필요한 경우 모바일 환경과 PC 환경을 구분하여 서로 다른 UI 구성을 적용할 수 있다.
- 환경 구분과 반응형 UI를 함께 사용하여 각 환경에서 사용하기 적합한 화면을 제공한다.
- 구체적인 UI 구성과 환경별 차이는 실제 기능 요구사항에 따라 결정한다.

## 7. 화면 테마

웹사이트는 다음 두 가지 테마를 지원한다.

- 다크 모드
- 화이트/라이트 모드

테마에 따라 텍스트, 배경, 입력 요소 및 기타 UI 요소가 적절하게 표시되도록 구성한다.

구체적인 테마 전환 방식과 세부 디자인은 추후 요구사항에 따라 정의한다.

## 8. 데이터와 소스코드의 분리

프로그램 소스코드와 사용자의 게임 데이터는 서로 분리한다.

예상 구조:

```
GitHub Repository
├── index.html
├── style.css
└── script.js

사용자 PC
└── game-data.json
```

사용자가 JSON 파일을 수정하거나 새로운 데이터를 저장하더라도 GitHub Repository의 소스코드에는 영향을 주지 않는다.

## 9. 프로젝트 개발 원칙

- 명시하지 않은 것은 임의로 해석 또는 결정해서 수정하지 않는다.
- 요구사항에 의해 간접적으로 영향을 받아 반드시 수정해야 정상적으로 작동하는 사항은 사용자에게 확인한 후, 해당 요구사항과 함께 작동하도록 변경 또는 추가한다.
- 기존 기능을 수정할 때 관련 기능에 미치는 영향을 확인한다.
- 계산 결과의 정확성을 중요하게 취급한다.
- JSON 데이터 구조는 향후 항목이 추가될 수 있도록 확장 가능하게 설계한다.
- HTML, CSS, JavaScript의 역할을 가능한 한 명확하게 분리한다.
- 반복적으로 사용되는 계산 로직은 적절한 JavaScript 함수로 분리한다.
- 사용자에게 표시되는 UI와 명칭은 가능한 한 한국어를 우선한다.
- 프로젝트 구조나 데이터 형식이 변경되면 README.md의 관련 내용도 함께 갱신한다.
- 기능을 추가하기 전에 기존 소스코드의 현재 상태를 확인한다.
- 코드 수정 시 기존에 구현되어 있는 기능을 불필요하게 제거하거나 변경하지 않는다.
- 요구사항이 모호하거나 계산 기준을 확인할 수 없는 경우 임의로 추측하지 않고 확인한다.

## 10. ChatGPT를 이용한 개발

이 Repository는 ChatGPT가 프로젝트의 현재 소스코드와 문서를 확인하면서 개발을 이어갈 수 있도록 구성한다.

ChatGPT가 작업할 때는 다음을 원칙으로 한다.

1. 현재 Repository의 실제 파일과 README.md를 우선 확인한다.
2. 기존 구현을 파악한 후 수정 범위를 결정한다.
3. 요구사항과 기존 구현이 충돌하는 경우 변경 전에 확인한다.
4. 명시하지 않은 사항은 임의로 해석하거나 결정하지 않는다. 요구사항의 간접적인 영향으로 반드시 필요한 변경이 있는 경우 사용자에게 확인한 후 함께 반영한다.
5. 필요한 파일만 수정한다.
6. 기능 변경 후 관련 코드의 일관성을 확인한다.
7. 데이터 구조를 변경하는 경우 기존 JSON 데이터와의 호환성도 고려한다.
8. 구현되지 않은 기능을 이미 구현된 것처럼 기록하지 않는다.
9. 프로젝트의 현재 상태를 README.md에 반영한다.

## 11. 현재 단계

현재는 프로젝트의 기본 방향과 개발 원칙만 정의한다.

아직 다음 사항은 확정하지 않는다.

- 구체적인 계산 기능
- 입력 항목
- 계산 공식
- 결과 표시 방식
- UI/UX 디자인
- JSON의 상세 스키마
- 모바일 화면의 상세 구성
- 모바일/PC 환경별 세부 UI 차이
- 다크 모드와 화이트/라이트 모드의 세부 디자인
- 필요한 JavaScript 라이브러리

이후 사용자가 구체적인 요구사항을 제시하면 해당 요구사항을 검토한 뒤 프로젝트에 반영한다.
