# table.html 요구사항 ## 역할 및 파일 관계 - 위치 기반 게임 데이터 입력 화면의 HTML 구조를 정의합니다. - 데이터 분류는 `pages_js/data-model.js`, 테이블 생성 및 상호작용은 `pages_js/table.js`, 저장/불러오기는 `pages_js/storage-manager.js`, 시각적 표현은 `pages_css/table.css`에서 관리합니다. - `table.html`은 데이터 모델, 테이블 스크립트, 저장/불러오기 스크립트를 순서대로 불러오며, 테마 상태를 쿠키와 페이지에 연결합니다. ## 테이블 구성 - 위치 Table 항목을 ID 오름차순으로 category-column에 표시하고, 제목은 위치 Table의 `name`을 사용합니다. - 각 열에는 해당 위치가 참조하는 속성 그룹에 속한 구분 Table 항목을 ID 오름차순으로 표시합니다. 속성 Table의 `name`은 화면에 표시하지 않습니다. - 기본 행은 구분 이름, 고정 표시 `+`, 값 입력 영역으로 구성합니다. - 위치 ID 1000(레벨)과 2000(팔라딘)은 세로 스택으로 묶고 두 열 사이 간격을 28px로 유지합니다. - 위치 ID 3000~8000의 6개 열은 슬라이드 탐색 영역에 배치합니다. 한 열을 기준으로 탐색하며, 인접 열의 가장자리는 페이드 영역에 일부 보일 수 있습니다. - ID 7000(전투 스킬(액티브))과 8000(전투 스킬(패시브))은 기본 행 없이 추가 행 버튼만 표시합니다. - 행 추가 버튼은 위치 ID 1000~2000 및 7000~8000에 표시합니다. ID 3000~6000에는 표시하지 않습니다. ## 입력·추가·삭제 - 값 입력은 숫자뿐 아니라 퍼센트 기호와 텍스트를 입력할 수 있도록 일반 텍스트 입력을 사용합니다. 구분 이름 입력과 입력값은 텍스트 선택 및 복사가 가능해야 합니다. - 일반 열의 추가 행은 구분 이름 텍스트 입력, 적용 형식 선택 목록, 값 입력, 삭제 버튼으로 구성합니다. - ID 7000 및 8000의 추가 행은 구분 이름 대신 선택 목록을 사용합니다. 목록은 `data-model.js`의 `sectionTable` 중 ID가 3000보다 큰 항목을 ID 오름차순으로 사용하며, 값은 구분 ID입니다. - 적용 형식 선택 목록은 `applicationTable`의 모든 항목을 표시 이름으로 보여주고 선택값으로 적용 ID를 사용합니다. - 행 추가 시 행 높이와 투명도가 전환되고 삭제 버튼이 페이드인합니다. 하단의 `+` 버튼은 문서 흐름에 따라 함께 이동합니다. - 추가 행을 삭제할 때 오른쪽 입력값이 비어 있지 않으면 사용자 정의 확인 팝업에 `(오른쪽 입력값 내용) 삭제하시겠습니까?`를 표시합니다. 비어 있으면 확인 없이 삭제합니다. 취소하면 행과 입력값을 유지합니다. - 사용자 정의 삭제 확인 팝업에는 `더 물어보지 마세요.` 체크박스가 있습니다. 체크한 뒤 삭제를 확정하면 이후 입력값이 있는 선택행 삭제 확인을 생략합니다. 취소한 경우 체크 상태를 설정에 반영하지 않습니다. - 삭제 확인 생략 설정은 페이지 실행 중 유지되며, 저장-브라우저 및 저장-파일 데이터에 포함됩니다. 불러오기 시 저장된 설정을 복원하고, 설정이 없는 이전 저장 데이터는 체크 해제 상태로 처리합니다. - 삭제가 확정되면 행이 높이와 투명도를 줄이며 접히고, X 버튼은 별도로 페이드아웃한 뒤 DOM에서 제거됩니다. - `prefers-reduced-motion: reduce` 설정에서는 해당 애니메이션을 생략하거나 줄입니다. ## 추가 행 드래그 및 위치 간 이동 - 사용자가 추가한 행만 드래그할 수 있으며 기본 행은 이동할 수 없습니다. 별도 핸들 없이 추가 행의 영역에서 드래그를 시작합니다. - 같은 위치 안에서 이동하면 구분 이름, 적용 형식, 값 입력을 모두 유지합니다. - 다른 위치로 이동하면 `입력 값만 이동됩니다.`라는 확인 메시지를 표시합니다. 확인 시 오른쪽 값 입력만 유지하고 구분 이름과 적용 형식을 초기화합니다. - 이동을 취소하거나 유효한 대상 밖에서 드래그를 끝내면 원래 위치와 모든 입력값을 복원합니다. - 드래그 중에는 원본 행 대신 placeholder가 레이아웃 공간을 차지하며, 복제 행이 포인터를 따라갑니다. 대상 그룹 강조와 placeholder는 드래그 종료 또는 취소 시 정리합니다. ## 슬라이드 탐색 - 슬라이드 대상은 위치 ID 3000~8000의 6개 열이며, 페이지 점도 열 순서에 맞춰 6개 표시합니다. - 좌우 화살표는 각각 한 열씩 이동합니다. 첫 열에서는 왼쪽 화살표를 `‖` 모양으로, 마지막 열에서는 오른쪽 화살표를 `‖` 모양으로 바꾸어 끝 페이지임을 표시합니다. 경계 상태의 화살표는 이동하지 않으며 계속 표시됩니다. - 뷰포트에서 시작한 수평 포인터 이동이 45px 이상이고 수평 이동이 수직 이동보다 뚜렷할 때 열을 이동합니다. 입력 필드, 선택 목록, 버튼 등에서 시작한 동작은 슬라이드로 처리하지 않습니다. - 페이지 점을 누르면 해당 열로 이동합니다. 대상 열의 실제 레이아웃 위치를 사용해 이동하므로 열 너비와 간격을 이동 계산에 반영합니다. - 기본 전환 시간은 300ms이며, 여러 열을 건너뛸 때도 전체 전환 시간 기준을 유지합니다. 동작 감소 설정에서는 전환 애니메이션을 생략합니다. ## 화면 배치 및 반응형 규칙 - 800×800px 고정 크기의 `.table-content-box` 래퍼는 사용하지 않습니다. 입력 테이블 콘텐츠는 `body` 안에 직접 배치합니다. - `h1`은 저장/불러오기 버튼과 다크모드 버튼 사이에서 기존보다 오른쪽으로 10px 이동하고, Y 좌표를 기존보다 10px 아래로 표시합니다. 글자 크기는 26px, 굵기는 600이며 장식선은 표시하지 않습니다. 제목 너비를 실제 측정하여 325px 이상에서는 `마비노기 모바일 계산기`를 한 줄로, 210px 이상 325px 미만에서는 `마비노기` / `모바일 계산기`를 두 줄로, 210px 미만에서는 `마비노기` / `모바일` / `계산기`를 세 줄로 표시합니다. 제목 단어 요소가 줄 배치에 따라 이동할 때 280ms 모션을 적용하고, 동작 감소 설정에서는 생략합니다. - `.table-area`는 페이지 너비를 사용하고 콘텐츠 묶음을 가로 중앙에 정렬합니다. `.level-paladin-stack`과 `.column-carousel`은 가능한 경우 가로로 나란히 배치하며, 두 묶음과 지정된 바깥 여백을 포함한 너비가 부족하면 자동으로 다음 줄에 배치합니다. 배치 상태가 나란히/위아래로 전환되는 순간에는 360ms FLIP 모션을 적용하고, 같은 배치 상태 안에서 발생하는 일반적인 너비 조정에는 모션을 적용하지 않습니다. 이 모션은 `window.resize`로 배치 상태 변경을 감지하고, `prefers-reduced-motion: reduce`에서는 생략합니다. - `.level-paladin-stack`은 좌우 margin 50px, `.column-carousel`은 좌우 margin 50px을 사용합니다. 두 콘텐츠 사이에서는 스택의 오른쪽 margin과 캐러셀의 왼쪽 margin이 서로 맞닿도록 합니다. 줄이 바뀔 때는 80px의 세로 간격을 둡니다. - 페이지 제목은 콘텐츠 박스 바깥에 두고, 제목의 장식선은 표시하지 않습니다. ## 테마 및 상단 버튼 - 테마 전환 버튼은 우측 상단에서 20px 떨어진 너비 50px, 높이 35px 위치에 표시하며, 기존 위치보다 Y축으로 45px 아래에 둡니다. 아이콘 크기는 유지합니다. 초승달과 태양 아이콘을 사용하며, 버튼 상태에 따라 아이콘과 접근성 레이블을 바꿉니다. 기존 테마 버튼 위치에는 같은 디자인의 `=` 아이콘 상단 메뉴 접기 버튼을 둡니다. - 쿠키 `darkmode`에 `true` 또는 `false`를 저장합니다. 쿠키가 없거나 `true`가 아니면 라이트모드로 시작합니다. 유효 기간은 315360000초이며 경로는 `/`, SameSite는 `Lax`입니다. HTTPS에서는 Secure 속성을 추가합니다. - 테마 상태에 따라 `body[data-theme]`, `aria-pressed`, `aria-label`, `title`을 갱신합니다. - 저장/불러오기 버튼은 왼쪽 상단에서 20px 떨어진 위치에 가로로 배치하고 버튼 사이 간격은 15px이며 버튼 높이는 30px입니다. 제목은 두 버튼 사이의 가용 공간을 사용하며, 화면 너비가 줄어 제목 문구 전체가 한 줄에 들어가지 않으면 단어별로 줄을 바꿉니다. - 저장/불러오기 버튼은 각각 하위 메뉴를 표시하며, 두 메뉴는 동시에 열리지 않습니다. 메뉴는 opacity가 변하는 fade in/out 전환을 사용합니다. - 상단 메뉴 접기 버튼은 기존 테마 버튼 위치에 너비 50px, 높이 30px로 표시하며, 아이콘은 `=` 모양입니다. 접기 버튼을 누르면 제목, 저장/불러오기 버튼, 다크모드 버튼이 위로 80px 이동하면서 페이드아웃합니다. 전체 페이지 전환 UI(`#full-page-pagination`)는 접기 대상에서 제외하여 표시 및 조작 상태를 유지합니다. 접힌 요소는 포인터 및 키보드 조작 대상에서 제외하되 기존 기능과 상태는 유지합니다. 다시 누르면 접기 대상 요소가 아래로 내려오며 페이드인하고 조작을 복원합니다. 동작 감소 설정에서는 이 모션을 생략합니다. - 저장 버튼 아래에는 `브라우저`, `파일` 버튼을 표시합니다. 불러오기 버튼 아래에도 같은 선택지를 표시하며, 각 메뉴의 왼쪽 가장자리는 해당 부모 버튼의 왼쪽 가장자리에 맞춥니다. - 하위 메뉴의 각 버튼은 90×30px입니다. 부모 버튼과 동일한 테두리(`var(--border-color)`), 둥근 모서리, 배경색, hover 및 다크모드 외형을 사용하되 그림자/후광 효과는 제외합니다. 라이트모드에서는 저장/불러오기 버튼과 네 하위 메뉴 버튼 모두 페이지 전환 옵션과 동일한 `var(--border-color)`를 사용하며, 다크모드에서는 별도 테두리 색상을 유지합니다. - 저장-브라우저는 현재 입력 상태를 `localStorage`에 기록합니다. 저장-파일은 동일한 데이터 객체를 JSON 파일로 다운로드합니다. 입력 변경만으로 자동 저장하지 않습니다. - 불러오기-브라우저는 `localStorage`의 마지막 저장 기록을 읽습니다. 불러오기-파일은 JSON 파일 선택 창을 열고, 선택한 파일을 검증한 뒤 브라우저 불러오기와 동일한 확인 및 복원 절차를 수행합니다. - 불러오기는 현재 입력 데이터가 저장 기록으로 대체된다는 확인 팝업을 표시합니다. 취소하면 현재 화면을 유지합니다. 파일 선택창은 `.json` 파일 형식 필터를 사용합니다. - JSON 파일과 localStorage는 서로 자동 동기화되지 않습니다. localStorage는 현재 브라우저의 해당 사이트 출처에 저장되며 서버나 다른 기기와 동기화되지 않습니다. - 저장/불러오기 오류는 원인을 설명하는 팝업으로 안내합니다. 상세 데이터 구조와 버전 규칙은 `readme_files/README_storage-manager.js`에서 관리합니다. - 버튼 터치 시 브라우저 기본 파란색 탭 하이라이트를 표시하지 않으며, 키보드 `:focus-visible` 표시를 유지합니다. ## 관련 파일 및 유지 조건 - `pages_js/data-model.js`: 위치·속성·구분·적용 데이터 - `pages_js/table.js`: 열·행 생성, 추가·삭제, 드래그, 슬라이드 탐색 - `pages_js/storage-manager.js`: 수동 저장 및 불러오기 - `pages_css/table.css`: 레이아웃, 테마, 색상 및 애니메이션 - `readme_files/README_storage-manager.js`: 저장 데이터 구조, 버전 관리, 오류 처리 요구사항 HTML 구조나 테마 상태 처리를 수정할 때는 테이블 스크립트와 CSS 선택자, 쿠키 복원 동작, 기존 입력값 보존에 미치는 영향을 함께 확인합니다. JSON 파일 기능과 localStorage 기능은 별개의 저장 방식으로 관리합니다. ## 상단 고정 영역 - `h1`, `.data-action-buttons`, `#theme-toggle`, `#full-page-pagination`은 `.page-header` 하나로 묶어 세로 스크롤 중에도 상단에 유지합니다. - 상단 고정 영역은 기존 페이지 배경색을 사용해 스크롤 콘텐츠가 뒤로 지나갈 때도 내부 UI가 가려지지 않도록 합니다. - `.page-header`의 하단에 `padding-bottom: 10px`을 추가하고 `.full-page-pagination`의 하단 여백 10px을 유지합니다. `#full-page-pagination`과 높이 20px의 세로 그라데이션은 `.pagination-fade-group`으로 묶습니다. 그라데이션은 그룹 바로 아래에서 배경색에서 투명으로 사라지며, 콘텐츠의 클릭을 가로채지 않습니다. 헤더 접기 동작 중에도 이 그룹은 표시 상태를 유지합니다. - 저장/불러오기 하위 메뉴의 표시 및 페이드 전환, 제목의 반응형 줄 배치와 280ms 모션, 테마 쿠키 처리, 페이지 전환 버튼의 선택 상태는 기존 동작을 유지합니다. - 기존 제목·페이지 전환 간격을 유지하고, 페이지 전환 영역 높이는 30px, `.table-area`의 상단 margin은 7px로 설정합니다. - 상단 버튼은 `.page-header`를 기준으로 기존 상단 20px, 좌우 20px 위치를 유지합니다. ## 전체 페이지 전환 UI - `h1` 아래 약 80px의 간격을 두고 `.full-page-pagination`을 배치하며, 해당 요소의 높이는 55px로 유지합니다. - 페이지 전환 박스는 투명 배경이며 테두리가 없습니다. 좌우 페이지 가장자리에서 각각 20px 떨어지도록 배치하고, 일반 화면에서는 최소 너비 410px을 사용합니다. 450px 미만 화면에서는 좌우 여백 20px을 유지하면서 최소 너비 제한을 해제해 가로 넘침을 방지합니다. - 내부에는 `스탯`, `룬`, `장비`, `기타` 버튼을 순서대로 가로 배치하고 버튼 사이 간격은 10px입니다. 사용 가능한 가로 공간에 따라 네 버튼이 동일 비율로 확장됩니다. - 현재 단계에서는 실제 페이지 데이터나 콘텐츠를 전환하지 않습니다. 버튼 클릭 시 선택 상태와 `aria-pressed`만 갱신하여 UI 반응을 확인할 수 있도록 합니다. 초기 선택은 `캐릭터 스탯`입니다. - 페이지 버튼은 기존 테마 변수와 160ms 색상 전환을 사용하며, 라이트/다크모드, hover 및 `:focus-visible` 상태를 지원합니다. 모바일 기본 탭 하이라이트를 제거하고 동작 감소 설정을 존중합니다. - `.full-page-pagination`을 `.table-area` 앞에 배치하여 해당 박스가 차지하는 공간이 테이블 영역의 세로 위치에 반영되도록 합니다. 페이지 전환 영역 및 네 옵션 버튼의 높이는 30px이며, `.table-area` 자체의 상단 margin은 7px을 사용합니다. ## 페이지 전환 옵션 및 공통 테두리 - 페이지 전환 옵션의 최소 너비는 75px입니다. 첫 번째 옵션의 문구는 `스탯`입니다. - 비활성 옵션의 배경은 현재 body 배경색과 동일하게 표시하고, `aria-pressed="true"`인 선택 옵션만 별도 배경색을 사용합니다. - 라이트모드에서 저장/불러오기 버튼, 하위 메뉴 버튼 및 테마 전환 버튼의 테두리 색상은 페이지 전환 옵션의 테두리 색상과 동일한 `var(--border-color)`를 사용합니다. 다크모드 테두리 색상은 기존 값을 유지합니다.
