# table.html 요구사항 ## 역할 및 파일 관계 - 위치 기반 게임 데이터 입력 화면의 HTML 구조를 정의합니다. - 데이터 분류는 `pages_js/data-model.js`, 테이블 생성 및 상호작용은 `pages_js/table.js`, 시각적 표현은 `pages_css/table.css`에서 관리합니다. - `table.html`은 데이터 모델과 테이블 스크립트를 순서대로 불러오며, 테마 상태를 쿠키와 페이지에 연결합니다. ## 테이블 구성 - 위치 Table 항목을 ID 오름차순으로 category-column에 표시하고, 제목은 위치 Table의 `name`을 사용합니다. - 각 열에는 해당 위치가 참조하는 속성 그룹에 속한 구분 Table 항목을 ID 오름차순으로 표시합니다. 속성 Table의 `name`은 화면에 표시하지 않습니다. - 기본 행은 구분 이름, 고정 표시 `+`, 값 입력 영역으로 구성합니다. - 위치 ID 1000(레벨)과 2000(팔라딘)은 세로 스택으로 묶고 두 열 사이 간격을 28px로 유지합니다. - 위치 ID 3000~8000의 6개 열은 슬라이드 탐색 영역에 배치합니다. 한 열을 기준으로 탐색하며, 인접 열의 가장자리는 페이드 영역에 일부 보일 수 있습니다. - ID 7000(전투 스킬(액티브))과 8000(전투 스킬(패시브))은 기본 행 없이 추가 행 버튼만 표시합니다. - 행 추가 버튼은 위치 ID 1000~2000 및 7000~8000에 표시합니다. ID 3000~6000에는 표시하지 않습니다. ## 입력·추가·삭제 - 값 입력은 숫자뿐 아니라 퍼센트 기호와 텍스트를 입력할 수 있도록 일반 텍스트 입력을 사용합니다. 구분 이름 입력과 입력값은 텍스트 선택 및 복사가 가능해야 합니다. - 일반 열의 추가 행은 구분 이름 텍스트 입력, 적용 형식 선택 목록, 값 입력, 삭제 버튼으로 구성합니다. - ID 7000 및 8000의 추가 행은 구분 이름 대신 선택 목록을 사용합니다. 목록은 `data-model.js`의 `sectionTable` 중 ID가 3000보다 큰 항목을 ID 오름차순으로 사용하며, 값은 구분 ID입니다. - 적용 형식 선택 목록은 `applicationTable`의 모든 항목을 표시 이름으로 보여주고 선택값으로 적용 ID를 사용합니다. - 행 추가 시 행 높이와 투명도가 전환되고 삭제 버튼이 페이드인합니다. 하단의 `+` 버튼은 문서 흐름에 따라 함께 이동합니다. - 추가 행을 삭제할 때 오른쪽 입력값이 비어 있지 않으면 `(오른쪽 입력값 내용) 삭제하시겠습니까?`를 확인합니다. 비어 있으면 확인 없이 삭제합니다. 취소하면 행과 입력값을 유지합니다. - 삭제가 확정되면 행이 높이와 투명도를 줄이며 접히고, X 버튼은 별도로 페이드아웃한 뒤 DOM에서 제거됩니다. - `prefers-reduced-motion: reduce` 설정에서는 해당 애니메이션을 생략하거나 줄입니다. ## 추가 행 드래그 및 위치 간 이동 - 사용자가 추가한 행만 드래그할 수 있으며 기본 행은 이동할 수 없습니다. 별도 핸들 없이 추가 행의 영역에서 드래그를 시작합니다. - 같은 위치 안에서 이동하면 구분 이름, 적용 형식, 값 입력을 모두 유지합니다. - 다른 위치로 이동하면 `입력 값만 이동됩니다.`라는 확인 메시지를 표시합니다. 확인 시 오른쪽 값 입력만 유지하고 구분 이름과 적용 형식을 초기화합니다. - 이동을 취소하거나 유효한 대상 밖에서 드래그를 끝내면 원래 위치와 모든 입력값을 복원합니다. - 드래그 중에는 원본 행 대신 placeholder가 레이아웃 공간을 차지하며, 복제 행이 포인터를 따라갑니다. 대상 그룹 강조와 placeholder는 드래그 종료 또는 취소 시 정리합니다. ## 슬라이드 탐색 - 슬라이드 대상은 위치 ID 3000~8000의 6개 열이며, 페이지 점도 열 순서에 맞춰 6개 표시합니다. - 좌우 화살표는 각각 한 열씩 이동하며 첫 열에서는 이전 화살표, 마지막 열에서는 다음 화살표를 숨깁니다. - 뷰포트에서 시작한 수평 포인터 이동이 45px 이상이고 수평 이동이 수직 이동보다 뚜렷할 때 열을 이동합니다. 입력 필드, 선택 목록, 버튼 등에서 시작한 동작은 슬라이드로 처리하지 않습니다. - 페이지 점을 누르면 해당 열로 이동합니다. 대상 열의 실제 레이아웃 위치를 사용해 이동하므로 열 너비와 간격을 이동 계산에 반영합니다. - 기본 전환 시간은 300ms이며, 여러 열을 건너뛸 때도 전체 전환 시간 기준을 유지합니다. 동작 감소 설정에서는 전환 애니메이션을 생략합니다. ## 화면 배치 및 반응형 규칙 - 800×800px 고정 크기의 `.table-content-box` 래퍼는 사용하지 않습니다. 입력 테이블 콘텐츠는 `body` 안에 직접 배치합니다. - `h1`은 너비 500px, 최대 너비 `calc(100vw - 40px)`이며 `left: 50vw`와 `translateX(-50%)`로 뷰포트 기준 중앙 정렬합니다. 하단 margin은 8px입니다. - `.table-area`는 페이지 너비를 사용하고 콘텐츠 묶음을 가로 중앙에 정렬합니다. `.level-paladin-stack`과 `.column-carousel`은 가능한 경우 가로로 나란히 배치하며, 두 묶음과 지정된 바깥 여백을 포함한 너비가 부족하면 자동으로 다음 줄에 배치합니다. - `.level-paladin-stack`은 좌우 margin 50px, `.column-carousel`은 오른쪽 margin 50px을 사용합니다. 줄이 바뀔 때는 80px의 세로 간격을 둡니다. - 페이지 제목은 콘텐츠 박스 바깥에 두고, 제목 아래 장식선을 표시합니다. ## 테마 및 상단 버튼 - 테마 전환 버튼은 우측 상단에서 20px 떨어진 50×50px 고정 위치에 표시합니다. 초승달과 태양 아이콘을 사용하며, 버튼 상태에 따라 아이콘과 접근성 레이블을 바꿉니다. - 쿠키 `darkmode`에 `true` 또는 `false`를 저장합니다. 쿠키가 없거나 `true`가 아니면 라이트모드로 시작합니다. 유효 기간은 315360000초이며 경로는 `/`, SameSite는 `Lax`입니다. HTTPS에서는 Secure 속성을 추가합니다. - 테마 상태에 따라 `body[data-theme]`, `aria-pressed`, `aria-label`, `title`을 갱신합니다. - 저장/불러오기 버튼은 왼쪽 상단에서 20px 떨어진 위치에 가로로 배치하고 버튼 사이 간격은 15px입니다. 현재 두 버튼은 UI만 있으며 실제 저장·불러오기 이벤트는 연결되어 있지 않습니다. - 버튼 터치 시 브라우저 기본 파란색 탭 하이라이트를 표시하지 않으며, 키보드 `:focus-visible` 표시를 유지합니다. ## 관련 파일 및 유지 조건 - `pages_js/data-model.js`: 위치·속성·구분·적용 데이터 - `pages_js/table.js`: 열·행 생성, 추가·삭제, 드래그, 슬라이드 탐색 - `pages_css/table.css`: 레이아웃, 테마, 색상 및 애니메이션 HTML 구조나 테마 상태 처리를 수정할 때는 테이블 스크립트와 CSS 선택자, 쿠키 복원 동작, 기존 입력값 보존에 미치는 영향을 함께 확인합니다. 입력값을 계산에 사용하거나 JSON으로 저장하는 기능은 현재 연결되어 있지 않습니다.
