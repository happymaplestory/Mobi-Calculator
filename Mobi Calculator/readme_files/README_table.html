# table.html 요구사항 ## 역할 및 파일 관계 - 위치 기반 게임 데이터 입력 화면의 HTML 구조를 정의합니다. - 데이터 분류는 `pages_js/data-model.js`, 테이블 생성 및 상호작용은 `pages_js/table.js`, 저장/불러오기는 `pages_js/storage-manager.js`, 시각적 표현은 `pages_css/table.css`에서 관리합니다. - `table.html`은 데이터 모델, 테이블 스크립트, 저장/불러오기 스크립트를 순서대로 불러오며, 테마 상태를 쿠키와 페이지에 연결합니다. ## 테이블 구성 - 위치 Table 항목을 ID 오름차순으로 category-column에 표시하고, 제목은 위치 Table의 `name`을 사용합니다. - 각 열에는 해당 위치가 참조하는 속성 그룹에 속한 구분 Table 항목을 ID 오름차순으로 표시합니다. 속성 Table의 `name`은 화면에 표시하지 않습니다. - 기본 행은 구분 이름, 고정 표시 `+`, 값 입력 영역으로 구성합니다. - 위치 ID 1000(레벨)과 2000(팔라딘)은 세로 스택으로 묶고 두 열 사이 간격을 28px로 유지합니다. - 위치 ID 3000~8000의 6개 열은 슬라이드 탐색 영역에 배치합니다. 한 열을 기준으로 탐색하며, 인접 열의 가장자리는 페이드 영역에 일부 보일 수 있습니다. - ID 7000(전투 스킬(액티브))과 8000(전투 스킬(패시브))은 기본 행 없이 추가 행 버튼만 표시합니다. - 행 추가 버튼은 위치 ID 1000~2000 및 7000~8000에 표시합니다. ID 3000~6000에는 표시하지 않습니다. ## 입력·추가·삭제 - 값 입력은 숫자뿐 아니라 퍼센트 기호와 텍스트를 입력할 수 있도록 일반 텍스트 입력을 사용합니다. 구분 이름 입력과 입력값은 텍스트 선택 및 복사가 가능해야 합니다. - 일반 열의 추가 행은 구분 이름 텍스트 입력, 적용 형식 선택 목록, 값 입력, 삭제 버튼으로 구성합니다. - ID 7000 및 8000의 추가 행은 구분 이름 대신 선택 목록을 사용합니다. 목록은 `data-model.js`의 `sectionTable` 중 ID가 3000보다 큰 항목을 ID 오름차순으로 사용하며, 값은 구분 ID입니다. - 적용 형식 선택 목록은 `applicationTable`의 모든 항목을 표시 이름으로 보여주고 선택값으로 적용 ID를 사용합니다. - 행 추가 시 행 높이와 투명도가 전환되고 삭제 버튼이 페이드인합니다. 하단의 `+` 버튼은 문서 흐름에 따라 함께 이동합니다. - 추가 행을 삭제할 때 오른쪽 입력값이 비어 있지 않으면 사용자 정의 확인 팝업에 `(오른쪽 입력값 내용) 삭제하시겠습니까?`를 표시합니다. 비어 있으면 확인 없이 삭제합니다. 취소하면 행과 입력값을 유지합니다. - 사용자 정의 삭제 확인 팝업에는 `더 물어보지 마세요.` 체크박스가 있습니다. 체크한 뒤 삭제를 확정하면 이후 입력값이 있는 선택행 삭제 확인을 생략합니다. 취소한 경우 체크 상태를 설정에 반영하지 않습니다. - 삭제 확인 생략 설정은 페이지 실행 중 유지되며, 저장-브라우저 및 저장-파일 데이터에 포함됩니다. 불러오기 시 저장된 설정을 복원하고, 설정이 없는 이전 저장 데이터는 체크 해제 상태로 처리합니다. - 삭제가 확정되면 행이 높이와 투명도를 줄이며 접히고, X 버튼은 별도로 페이드아웃한 뒤 DOM에서 제거됩니다. - `prefers-reduced-motion: reduce` 설정에서는 해당 애니메이션을 생략하거나 줄입니다. ## 추가 행 드래그 및 위치 간 이동 - 사용자가 추가한 행만 드래그할 수 있으며 기본 행은 이동할 수 없습니다. 별도 핸들 없이 추가 행의 영역에서 드래그를 시작합니다. - 같은 위치 안에서 이동하면 구분 이름, 적용 형식, 값 입력을 모두 유지합니다. - 다른 위치로 이동하면 `입력 값만 이동됩니다.`라는 확인 메시지를 표시합니다. 확인 시 오른쪽 값 입력만 유지하고 구분 이름과 적용 형식을 초기화합니다. - 다른 위치로 이동하는 확인 팝업이 표시되는 동안에는 포인터를 따라가던 복제 행을 숨깁니다. 팝업이 닫히면 기존 드래그 종료 및 정리 절차를 그대로 수행하며, 확인 생략 설정으로 팝업이 표시되지 않는 경우에는 별도 숨김 처리를 하지 않습니다. - 이동을 취소하거나 유효한 대상 밖에서 드래그를 끝내면 원래 위치와 모든 입력값을 복원합니다. - 드래그 중에는 원본 행 대신 placeholder가 레이아웃 공간을 차지하며, 복제 행이 포인터를 따라갑니다. 대상 그룹 강조와 placeholder는 드래그 종료 또는 취소 시 정리합니다. ## 슬라이드 탐색 - 슬라이드 대상은 위치 ID 3000~8000의 6개 열이며, 페이지 점도 열 순서에 맞춰 6개 표시합니다. - 좌우 화살표는 각각 한 열씩 이동합니다. 첫 열에서는 왼쪽 화살표를 `‖` 모양으로, 마지막 열에서는 오른쪽 화살표를 `‖` 모양으로 바꾸어 끝 페이지임을 표시합니다. 경계 상태의 화살표는 이동하지 않으며 계속 표시됩니다. - 뷰포트에서 시작한 수평 포인터 이동이 45px 이상이고 수평 이동이 수직 이동보다 뚜렷할 때 열을 이동합니다. 입력 필드, 선택 목록, 버튼 등에서 시작한 동작은 슬라이드로 처리하지 않습니다. - 페이지 점을 누르면 해당 열로 이동합니다. 대상 열의 실제 레이아웃 위치를 사용해 이동하므로 열 너비와 간격을 이동 계산에 반영합니다. - 기본 전환 시간은 300ms이며, 여러 열을 건너뛸 때도 전체 전환 시간 기준을 유지합니다. 동작 감소 설정에서는 전환 애니메이션을 생략합니다. ## 화면 배치 및 반응형 규칙 - 800×800px 고정 크기의 `.table-content-box` 래퍼는 사용하지 않습니다. 입력 테이블 콘텐츠는 `body` 안에 직접 배치합니다. - `h1`은 저장/불러오기 버튼과 다크모드 버튼 사이에서 기존보다 오른쪽으로 10px 이동하고, Y 좌표를 기존보다 10px 아래로 표시합니다. 글자 크기는 26px, 굵기는 600이며 장식선은 표시하지 않습니다. 제목 너비를 실제 측정하여 325px 이상에서는 `마비노기 모바일 계산기`를 한 줄로, 210px 이상 325px 미만에서는 `마비노기` / `모바일 계산기`를 두 줄로, 210px 미만에서는 `마비노기` / `모바일` / `계산기`를 세 줄로 표시합니다. 제목 단어 요소가 줄 배치에 따라 이동할 때 280ms 모션을 적용하고, 동작 감소 설정에서는 생략합니다. 제목의 실제 측정 너비가 125px 이하이면 opacity를 0으로 페이드아웃하고, 125px를 초과하면 페이드인합니다. 이 표시 전환은 260ms이며 제목의 레이아웃 공간은 유지합니다. - `.table-area`는 페이지 너비를 사용하고 콘텐츠 묶음을 가로 중앙에 정렬합니다. `.level-paladin-stack`과 `.column-carousel`은 가능한 경우 가로로 나란히 배치하며, 두 묶음과 지정된 바깥 여백을 포함한 너비가 부족하면 자동으로 다음 줄에 배치합니다. 가로 배치일 때 `.level-paladin-stack`의 `margin-top`은 58px, 세로 배치일 때는 10px입니다. 배치 상태가 나란히/위아래로 전환되는 순간에는 두 콘텐츠 묶음에 260ms FLIP 슬라이드 모션을 적용하며, margin 변경으로 발생하는 이동도 이 모션에 포함합니다. 같은 배치 상태 안에서 발생하는 일반적인 너비 조정에는 모션을 적용하지 않습니다. 배치 상태는 `window.resize`에서 감지하며, `prefers-reduced-motion: reduce`에서는 이동 모션을 생략합니다. - `.level-paladin-stack`은 기본 좌우 margin 50px을 사용합니다. `.table-area`가 `is-stacked` 상태일 때는 왼쪽 margin 43px, 오른쪽 margin 57px을 사용하며, 이 상태 전환에 따른 margin 및 내부 박스 위치 이동은 260ms `cubic-bezier(.22,.72,.22,1)` transition으로 부드럽게 연결합니다. `.column-carousel`은 좌우 margin 50px을 사용합니다. 두 콘텐츠 사이에서는 스택의 오른쪽 margin과 캐러셀의 왼쪽 margin이 서로 맞닿도록 합니다. 줄이 바뀔 때는 80px의 세로 간격을 둡니다. - 페이지 제목은 콘텐츠 박스 바깥에 두고, 제목의 장식선은 표시하지 않습니다. ## 테마 및 상단 버튼 - 테마 전환 버튼은 우측 상단에서 20px 떨어진 너비 50px, 높이 35px 위치에 표시하며, 상단 위치는 55px입니다. 기존 위치보다 Y축으로 45px 아래에 둡니다. 아이콘 크기는 유지합니다. 초승달과 태양 아이콘을 사용하며, 버튼 상태에 따라 아이콘과 접근성 레이블을 바꿉니다. 기존 테마 버튼 위치에는 같은 디자인의 `=` 아이콘 상단 메뉴 접기 버튼을 둡니다. - 쿠키 `darkmode`에 `true` 또는 `false`를 저장합니다. 쿠키가 없거나 `true`가 아니면 라이트모드로 시작합니다. 유효 기간은 315360000초이며 경로는 `/`, SameSite는 `Lax`입니다. HTTPS에서는 Secure 속성을 추가합니다. - 테마 상태에 따라 `body[data-theme]`, `aria-pressed`, `aria-label`, `title`을 갱신합니다. - 저장/불러오기 버튼은 왼쪽 상단에서 20px 떨어진 위치에 하나의 가로형 버튼 세트로 배치합니다. 두 버튼 사이의 구분 박스는 유지하되 내부의 `|` 문자나 아이콘은 표시하지 않습니다. 두 버튼은 외곽 테두리와 둥근 모서리를 공유하며 높이는 30px입니다. 저장 모드는 주황색 계열, 불러오기 모드는 파란색 계열의 보색 대비가 뚜렷한 hover 배경색을 사용하고, 선택된 버튼은 메뉴가 열린 동안 해당 hover 배경색을 유지합니다. 다크모드에서도 같은 색상 대비를 유지하도록 각각 더 어두운 주황색과 파란색 계열을 사용합니다. 제목은 버튼 세트와 다크모드 버튼 사이의 가용 공간을 사용하며, 화면 너비가 줄어 제목 문구 전체가 한 줄에 들어가지 않으면 단어별로 줄을 바꿉니다. - 저장/불러오기 버튼 중 하나를 선택하면 공통 하위 메뉴를 표시합니다. 저장과 불러오기 중 한 모드만 활성화되며, 두 모드의 하위 메뉴가 따로 존재하지 않습니다. 공통 하위 메뉴는 저장 모드에서 `브라우저 저장`, `파일 저장`, 불러오기 모드에서 `브라우저 로드`, `파일 로드` 텍스트를 표시합니다. 하위 메뉴는 부모 `저장 | 불러오기` 버튼 세트의 가로 길이와 같고, 부모 버튼 세트 바로 아래에 간격 없이 붙여 표시합니다. 두 세트가 맞닿는 경계에서도 부모 버튼 하단과 첫 번째 하위 버튼 상단의 둥근 모서리를 유지합니다. 활성 모드에 따라 두 버튼의 기능과 배경색을 전환합니다. 메뉴는 opacity가 변하는 fade in/out 전환을 사용합니다. - 브라우저 뷰포트의 너비 또는 높이 변경이 감지되면, 공통 하위 메뉴가 열린 상태(`aria-hidden="false"`)에서 메뉴를 닫고 `aria-hidden="true"`로 전환합니다. 닫힘은 기존 페이드 전환을 유지합니다. - 상단 메뉴 접기 버튼은 기존 테마 버튼 위치에 너비 50px, 높이 30px로 표시하며, 아이콘은 `=` 모양입니다. 접기 버튼을 누르면 제목, 저장/불러오기 버튼, 다크모드 버튼이 위로 80px 이동하면서 페이드아웃합니다. `.page-header`의 실제 높이는 접기·펼치기 상태 변경 전후의 높이를 측정해 260ms cubic-bezier 전환으로 부드럽게 변경합니다. `.table-area`에는 별도 transform 보정을 적용하지 않고 문서 흐름에서 헤더 높이 전환을 그대로 따라가도록 하여, 헤더와 테이블 사이의 이동이 동일한 시간축으로 연결되게 합니다. 전환 중 다시 버튼을 누르면 현재 화면 높이에서 새 전환을 시작합니다. 헤더 내부 애니메이션과 기존 페이지네이션 보정은 유지합니다. `prefers-reduced-motion: reduce`에서는 헤더 높이 전환을 적용하지 않습니다. 전체 페이지 전환 UI(`#full-page-pagination`)는 접기 대상에서 제외하여 표시 및 조작 상태를 유지합니다. 접힌 요소는 포인터 및 키보드 조작 대상에서 제외하되 기존 기능과 상태는 유지합니다. 다시 누르면 접기 대상 요소가 아래로 내려오며 페이드인하고 조작을 복원합니다. 동작 감소 설정에서는 이 모션을 생략합니다. - 통합 버튼 세트 아래에는 `브라우저 저장`/`파일 저장` 또는 `브라우저 로드`/`파일 로드` 버튼을 공통으로 표시합니다. 저장 모드에서는 저장 기능을, 불러오기 모드에서는 불러오기 기능을 실행하며, 활성 모드의 hover 배경색을 공통 하위 버튼 세트에도 적용합니다. 하위 버튼의 기본 배경색은 부모 저장/불러오기 버튼의 색상을 기준으로 HSL 채도를 20% 낮춥니다. 라이트모드에서는 HSL 명도를 20% 높이고 다크모드에서는 20% 낮춥니다. 하위 버튼에 hover하면 부모 버튼의 해당 모드 색상과 동일한 배경색을 사용합니다. - 저장/불러오기 오류는 원인을 설명하는 팝업으로 안내합니다. 상세 데이터 구조와 버전 규칙은 `readme_files/README_storage-manager.js`에서 관리합니다. - 버튼 터치 시 브라우저 기본 파란색 탭 하이라이트를 표시하지 않으며, 키보드 `:focus-visible` 표시를 유지합니다. ## 관련 파일 및 유지 조건 - `pages_js/data-model.js`: 위치·속성·구분·적용 데이터 - `.full-page-pagination`은 상단 및 하단 margin을 모두 0px로 설정하고 높이는 34px로 유지합니다. `h1`이 한 줄(`data-title-layout="single"`)인 경우에만 페이지네이션의 왼쪽 여백을 215px, 오른쪽 여백을 90px로 설정하고 `top: 0`으로 기본 Y축 위치를 유지합니다. 펼친 상태에서 화면 너비가 585px 미만이면 `.full-page-pagination`과 `#page-content-stage`를 함께 `translateY(35px)` 이동하고, 470px 미만이면 함께 `translateY(70px)` 이동합니다. 두 요소는 모두 260ms `cubic-bezier(.22,.72,.22,1)` transform 전환으로 병렬 이동하며, 페이지네이션의 X축 배치 규칙은 그대로 유지됩니다. 공통 덮개 `.header-cover-layer`는 해당 분기에서 `--header-y-offset`을 35px 또는 70px로 설정해 하단 그라데이션까지 같은 거리만큼 확장합니다. `#header-collapse-toggle`의 `aria-expanded="false"` 상태에서는 이 너비별 Y축 보정을 적용하지 않습니다. 이때 페이지 메뉴는 `width: auto`, `min-width: 0`, 왼쪽 여백 20px, 오른쪽 여백 90px 규칙을 사용합니다. 펼친 상태에서도 고정된 `calc()` 너비를 사용하지 않고 좌우 margin을 제외한 가로 공간을 자동으로 채웁니다. `h1[data-title-layout="three"]`이면 오른쪽 여백을 20px로 줄이며, 확보된 공간만큼 박스가 자동 확장됩니다. 페이지네이션의 좌우 margin이 바뀌거나 페이지 가로 너비가 바뀔 때 모두 좌우 끝에 맞춰 너비와 위치가 자연스럽게 따라가야 하며, `width`, `margin-left`, `margin-right` 전환은 260ms `cubic-bezier(.22,.72,.22,1)` 애니메이션으로 부드럽게 연결합니다. `#page-content-stage`에는 위쪽 margin 40px과 기존 padding 20px을 적용합니다. 접기/펼치기 상태 전환 시 `width`, `margin-left`, `margin-right`를 260ms `cubic-bezier(.22,.72,.22,1)`로 애니메이션해 페이지네이션의 가로 크기와 좌우 위치가 자연스럽게 변경되도록 합니다. 페이지 가로 너비 변경 시에도 좌우 margin을 유지하며 사용 가능한 공간에 맞춰 너비가 자동 조정되어야 하고, margin 변경과 화면 너비 변경 모두에서 가로 크기 및 위치의 움직임이 부드럽게 유지되어야 합니다. `#full-page-pagination` 자체의 접힌 상태 `transform: translateY(-20px)` 전환에는 `transition: transform 260ms cubic-bezier(.22,.72,.22,1)`을 적용합니다. 펼친 상태의 반응형 `translateY(35px)` 및 `translateY(70px)` 이동은 유지합니다. - 페이지 전환 박스는 테두리가 없으며, 배경색은 `body`와 동일한 `var(--background-color)`를 사용합니다. 라이트/다크모드 전환 시 배경색도 `160ms ease`로 부드럽게 전환합니다. 좌우 페이지 가장자리에서 각각 20px 떨어지도록 배치하고, 일반 화면에서는 최소 너비 410px을 사용합니다. 450px 미만 화면에서는 좌우 여백 20px을 유지하면서 최소 너비 제한을 해제해 가로 넘침을 방지합니다. - 내부에는 `스탯`, `룬`, `장비`, `기타` 버튼을 순서대로 가로 배치하고 버튼 사이 간격은 10px입니다. 사용 가능한 가로 공간에 따라 네 버튼이 동일 비율로 확장됩니다. - `스탯`, `룬`, `장비`, `기타` 버튼은 각각 독립된 최상위 페이지로 동작하며, 클릭 시 선택 상태와 `aria-pressed`를 갱신합니다. 최초 방문 및 새로고침의 기본 페이지는 `스탯`입니다. 기존 입력 콘텐츠(`#table-area`)는 스탯 페이지에서만 표시하고, 페이지를 전환해도 입력 DOM과 입력값을 제거하지 않아 돌아왔을 때 상태를 유지합니다. `#runes-page`는 룬 버튼의 `aria-pressed="true"` 상태이고 패널의 `hidden` 속성이 해제된 경우에만 표시합니다. 룬 버튼의 `aria-pressed="false"` 상태에서는 전환 중에도 룬 페이지가 표시되지 않도록 합니다. - `룬` 페이지는 테스트 문구가 없는 접근성 레이블 `룬 페이지`를 사용하며, 배경은 완전히 투명합니다. 내부 콘텐츠는 `#runes-select-box`와 `#runes-search-box` 두 박스로 구성합니다. 두 박스는 각각 가로 350px이며, 선택 박스 높이는 400px, 검색 박스 높이는 750px입니다. 두 박스 모두 margin은 상단 15px, 좌우 25px, 하단 15px이며 선택 박스와 검색 박스의 배경색은 모두 임시로 `#888888`입니다. 모든 페이지 콘텐츠 패널은 비활성 페이지에서 `hidden` 속성이 실제 표시를 차단하도록 해야 하며, 스탯 페이지를 선택했을 때 룬 페이지가 함께 보이면 안 됩니다. 두 박스는 사용 가능한 가로 폭에 따라 나란히 또는 위아래로 배치되고, 세로 배치에서는 `.table-area.is-stacked`와 공유하는 CSS 규칙으로 `row-gap: 30px`을 적용합니다. 배치 전환 시 260ms `cubic-bezier(.22,.72,.22,1)` FLIP 이동 모션을 적용합니다. `prefers-reduced-motion: reduce`에서는 이동 모션을 생략합니다. `장비`, `기타` 페이지의 기존 테스트용 콘텐츠 박스는 800×800px이며 배경색은 각각 `#88bb88`, `#8888bb`입니다. - 페이지 전환 시 이전 콘텐츠는 클릭 즉시 260ms 동안 투명해지면서 아래로 24px 이동하고 `scale(0.94)`로 축소되어 바닥으로 잠겨 사라지는 듯한 효과를 냅니다. 새 콘텐츠는 100ms 지연 후 260ms 동안 투명도 0→1로 나타나며, 이전 페이지 버튼보다 왼쪽 페이지를 선택하면 왼쪽에서 중앙으로, 오른쪽 페이지를 선택하면 오른쪽에서 중앙으로 32px 이동합니다. 전환 중에는 패널을 겹쳐 표시하되 상단 inset에 `.page-content-stage`의 `padding-top: 20px`을 반영해 일반 상태와 동일한 콘텐츠 시작 위치를 유지합니다. 콘텐츠 영역 높이는 패널 높이에 stage의 상단 padding과 해당 패널의 상단 margin을 더한 값으로 조정해 padding이 전환 중 사라지거나 높이 계산에서 누락되지 않게 합니다. 연속 전환 시 이전 애니메이션을 취소하고 현재 페이지 상태를 정리하며, `prefers-reduced-motion: reduce`에서는 모션 없이 전환합니다. - 페이지 버튼은 기존 테마 변수와 160ms 색상 전환을 사용하며, 라이트/다크모드, hover 및 `:focus-visible` 상태를 지원합니다. 모바일 기본 탭 하이라이트를 제거하고 동작 감소 설정을 존중합니다. - `스탯`, `룬`, `장비`, `기타` 페이지 전환 옵션에는 음영 또는 발광 효과(`box-shadow`)를 적용하지 않습니다. 라이트모드와 다크모드 모두 동일하게 적용하며, 버튼의 배경색 전환, 테두리, 선택 상태 및 hover 동작은 유지합니다. - `.full-page-pagination`은 `.table-area` 앞의 실제 문서 흐름에 직접 포함합니다. 공통 덮개와 하단 그라데이션은 절대 배치되어 문서 흐름 높이를 추가하지 않습니다. 페이지 전환 영역 및 네 옵션 버튼의 높이는 34px이며, `.table-area` 자체의 상단 margin은 7px을 사용합니다. ## 페이지 전환 옵션 및 공통 테두리 - 페이지 전환 옵션의 최소 너비는 75px입니다. 첫 번째 옵션의 문구는 `스탯`입니다. - 비활성 옵션의 배경은 현재 body 배경색과 동일하게 표시하고, `aria-pressed="true"`인 선택 옵션만 별도 배경색을 사용합니다. - 라이트모드에서 저장/불러오기 버튼, 하위 메뉴 버튼 및 테마 전환 버튼의 테두리 색상은 페이지 전환 옵션의 테두리 색상과 동일한 `var(--border-color)`를 사용합니다. 다크모드 테두리 색상은 기존 값을 유지합니다. ## 저장/불러오기 하위 메뉴가 열린 상태의 위치 조정 - 상단 메뉴가 펼쳐져 있고 (#header-collapse-toggle의 aria-expanded="true"), 공통 하위 메뉴 (#action-submenu)의 aria-hidden이 false이며 제목이 한 줄 (h1[data-title-layout="single"])이면 공통 덮개 .header-cover-layer의 하단을 60px 더 확장하고, #full-page-pagination과 #page-content-stage를 각각 아래로 60px 이동합니다. - 같은 조건에서 제목이 두 줄 (h1[data-title-layout="two"])이면 공통 덮개 하단을 30px 더 확장하고, #full-page-pagination과 #page-content-stage를 각각 아래로 30px 이동합니다. 제목이 세 줄 (h1[data-title-layout="three"])이면 이 추가 이동을 적용하지 않습니다. - 기존 접기/펼치기, 반응형 위치 보정 및 페이지 콘텐츠 전환을 보존하기 위해 페이지 메뉴와 콘텐츠 영역은 별도 CSS translate 속성을 사용합니다. 제목이 single, two, three 사이에서 어느 방향으로 변경되더라도 덮개 bottom, 페이지 메뉴 translate, 콘텐츠 translate는 기존 260ms cubic-bezier(.22,.72,.22,1) 전환으로 부드럽게 이동합니다. - `.page-content-stage`의 `translate` 전환은 기본 CSS 규칙에서 항상 유지하고, 조건부 규칙에는 목표 이동값만 설정합니다. 특히 제목이 한 줄인 상태에서 하위 메뉴가 열림에서 닫힘으로 바뀔 때도 60px 이동이 부드럽게 되돌아가야 하며, 전환 선언을 조건부 규칙 안으로 옮겨 순간 이동이 재발하지 않도록 합니다. ## 룬 검색 상자 - 설명 팝업은 `.rune-description-overlay[hidden]`일 때 반드시 `display: none !important`로 숨깁니다. 룬 페이지가 비활성 상태여도 팝업 요소가 문서에 생성되어 있을 수 있으므로, HTML의 `hidden` 속성이 CSS의 `display: grid` 선언에 덮이지 않도록 합니다. - `#runes-search-box`에는 개발 테스트 페이지의 룬 검색 기능을 이식하여 `pages_js/runes-data.js`의 `RUNES.items`를 표시합니다. 검색 상자 내부에 검색·필터·정렬·페이지네이션 및 설명 팝업을 포함합니다. - 등급 필터는 `신화`, `전설`; 부위 필터는 `무기`, `방어구`, `엠블럼`이며 기본 활성화 상태입니다. 비활성화된 필터 조건은 검색 결과에서 제외합니다. - 검색은 룬 이름과 설명을 대상으로 하며, 이름 가나다순/역순 정렬을 지원합니다. 페이지당 10개를 표시하고, 결과가 10개를 초과할 때만 페이지네이션을 표시합니다. - 표에는 `부위`, `이름`만 표시하며, 헤더(`thead`)는 노출하지 않습니다. 부위 열은 60px 고정 너비이며, 등급은 행의 배경색과 테두리로만 구분합니다. 전설은 옅은 오렌지색, 신화는 옅은 개나리색을 사용하며 다크모드에서는 같은 등급 계열의 어두운 색으로 전환합니다. 표 외곽은 다른 UI 박스와 같이 네 모서리를 둥글게 처리합니다. - 행 클릭 또는 Enter/Space로 룬 설명 팝업을 열고, 닫기 버튼·바깥 영역 클릭·Escape 키로 닫습니다. 설명의 줄바꿈은 유지합니다. 팝업은 table.html의 사용자 정의 확인 팝업과 동일한 테마 대응 외형과 등장 모션을 사용합니다. - 검색 상자 안의 필터·검색·정렬·페이지 버튼은 table.html의 `--background-color`, `--surface-color`, `--text-color`, `--border-color`, `--hover-color` 변수를 사용하여 기존 hover 및 다크모드 디자인과 통일합니다. 검색 입력창을 포함한 모든 조작 요소는 hover 상태를 지원하고, 검색 입력창의 배경색 전환은 160ms로 동작합니다. 모션은 `prefers-reduced-motion: reduce` 설정을 존중합니다. - 검색 상자의 기존 350×750px 크기와 반응형 배치 및 페이지 전환 동작은 유지합니다. `runes-page.is-stacked` 상태에서도 검색 상자의 높이가 줄어들지 않아야 하며, 콘텐츠가 상자 안에 맞도록 구성해 내부 스크롤이 발생하지 않게 합니다.
