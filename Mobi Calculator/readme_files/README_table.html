# table.html 요구사항 ## 역할 마비노기 모바일 계산기의 위치 기반 게임 데이터 입력 테이블을 표시합니다. 데이터 분류는 `pages_js/data-model.js`에서 관리하고, 화면 생성은 `pages_js/table.js`, 시각적 표현은 `pages_css/table.css`에서 관리합니다. ## 화면 구성 - 위치 Table의 각 항목을 하나의 category-column으로 표시합니다. - category-column은 위치 ID 오름차순으로 배치합니다. - 각 category-column의 제목은 위치 Table의 `name` 값을 사용합니다. - 각 category-group에는 위치 항목이 참조하는 속성 그룹에 속한 구분 Table 항목을 행으로 표시합니다. - 속성 Table의 `name` 값은 화면에 표시하지 않습니다. - 기본 행은 첫 번째 열에 구분 Table의 `name`, 두 번째 열에 `+`, 세 번째 열에 사용자 입력 영역을 배치합니다. - 기본 행의 두 번째 열은 구분 Table의 적용 형식과 관계없이 `+`로 고정합니다. - ID 7000과 8000은 별도 지시가 있을 때까지 제목만 표시하며, 행 추가 기능도 표시하지 않습니다. - ID 1000~6000의 각 테이블 하단에는 행 추가 버튼을 표시합니다. - 행 추가 버튼을 누르면 새 행이 갑자기 나타나지 않고, 행이 부드럽게 펼쳐지면서 하단의 `+` 버튼도 함께 아래로 이동해야 합니다. - 새 행의 X 삭제 버튼도 행이 펼쳐지는 흐름에 맞춰 자연스럽게 페이드인해야 합니다. - 추가 행에는 구분 이름 텍스트 입력, 적용 형식 선택 목록, 값 텍스트 입력, 행 삭제 버튼을 표시합니다. - 추가 행의 적용 형식 선택 목록은 적용 Table의 모든 항목을 이름으로 표시하며, 선택값은 적용 항목 ID를 사용합니다. - 추가 행의 삭제 버튼을 누르면 오른쪽 입력값이 비어 있지 않을 때만 "(오른쪽 입력값 내용) 삭제하시겠습니까?"라는 확인 메시지를 표시합니다. 확인하면 해당 행을 삭제하고, 취소하면 행과 모든 입력값을 그대로 유지합니다. 오른쪽 입력값이 비어 있으면 확인 메시지 없이 즉시 삭제합니다. 삭제 버튼은 행 높이를 기준으로 세로 중앙에 정렬합니다. - 기존 행은 이동할 수 없으며, 사용자가 추가한 행만 드래그할 수 있습니다. 별도의 드래그 핸들 없이 추가 행의 어느 영역에서든 드래그를 시작할 수 있습니다. - 행은 마우스로 끌어 같은 위치 안에서 순서를 변경할 수 있습니다. 드래그 중 원본 행은 흐리게 표시하고, 이동 위치에는 placeholder를 표시하며, 드래그 중인 행은 포인터를 따라 표시합니다. placeholder 위치가 바뀔 때 주변 추가 행은 부드럽게 밀려나는 애니메이션을 표시합니다. - 추가 행끼리만 드래그로 순서를 변경할 수 있으며, 기본 행은 이동할 수 없습니다. - 같은 위치에서 순서를 변경하면 구분 이름, 적용 형식, 오른쪽 값 입력을 모두 유지합니다. - 다른 위치로 행을 이동할 때는 "입력 값만 이동됩니다."라는 확인 메시지를 표시합니다. - 다른 위치로 이동을 확인하면 오른쪽 값 입력만 유지하고, 구분 이름 입력과 적용 형식 선택은 초기화한 뒤 대상 위치로 이동합니다. - 다른 위치로 이동을 취소하면 원래 위치와 구분 이름, 적용 형식, 오른쪽 값 입력을 모두 유지합니다. - 유효한 대상 위치가 아닌 곳에서 드래그를 끝내면 원래 위치와 모든 입력값을 복원합니다. - 포인터 입력이 취소되는 등 드래그가 중단되어도 원본 행과 입력값을 보존하고, 드래그용 복제 행·placeholder·대상 강조 상태를 정리합니다. - 화면 너비가 바뀌어도 category-column의 배치 순서와 열 구성을 자동으로 재계산하지 않습니다. 좁은 화면에서는 가로 스크롤로 확인합니다. ## 입력 영역 - 값 입력은 숫자뿐 아니라 `%` 및 필요한 텍스트를 입력할 수 있도록 `input type="text"`를 사용합니다. - 추가 행의 구분 이름은 텍스트로 직접 입력할 수 있어야 합니다. - 추가 행의 적용 형식은 선택 목록에서 고를 수 있어야 합니다. - 입력값과 구분 이름은 텍스트 선택 및 복사가 가능해야 합니다. ## 테마와 hover - 행 hover 배경색은 단일 회색이 아니라 해당 category-card의 제목 색상과 어울리는 색상 계열을 사용합니다. - 추가 및 삭제 버튼의 테두리와 hover 색상은 해당 category-card 테마를 따릅니다. ## 데이터 참조 규칙 - `table.js`는 `data-model.js`의 `MOBI_DATA_MODEL`을 참조합니다. - 위치 항목은 `locationTable`의 ID, 이름, `attributeGroups`를 사용합니다. - 구분 항목은 `sectionTable`의 `id`, `group`, `name`을 사용합니다. - 행은 위치 항목이 참조하는 속성 그룹에 해당하는 구분 항목을 모아 구분 ID 오름차순으로 표시합니다. - 추가 행의 적용 목록은 `applicationTable`에서 생성합니다. - 입력값을 계산에 사용하거나 JSON으로 저장하는 기능은 이 변경에 포함되지 않습니다. ## 관련 파일 - `table.html`: 데이터 모델과 화면 스크립트 연결 - `pages_js/data-model.js`: 위치·속성·구분·적용 데이터 정의 - `pages_js/table.js`: 위치별 열과 행 생성 및 추가/삭제 동작 - `pages_css/table.css`: 레이아웃 및 시각적 표현 ## 행 삭제 애니메이션 - 삭제가 확정되면 해당 행이 즉시 사라지지 않고 높이와 투명도가 줄어들며 접힌다. - 삭제 행이 접히는 동안 아래쪽 행과 하단의 `+` 버튼은 문서 흐름에 따라 위로 이동하여 빈 공간을 덮는다. - 삭제되는 행의 X 버튼도 행이 접히는 동안 자연스럽게 페이드아웃해야 한다. - 입력값이 있을 때 표시하는 기존 삭제 확인창과 취소 동작을 유지한다. 입력값이 비어 있으면 확인창 없이 애니메이션 후 삭제한다. - 시스템의 동작 감소 설정이 활성화되어 있으면 애니메이션을 생략한다. ## 레벨 및 팔라딘 열 배치와 연동 애니메이션 - `category-title`이 `레벨`인 `category-column` 바로 아래에 `category-title`이 `팔라딘`인 `category-column`을 세로로 배치한다. 팔라딘 열은 다른 열과 나란히 배치하지 않는다. - 레벨과 팔라딘 열은 하나의 세로 스택으로 묶고, 두 열 사이 간격은 기존 열 사이 간격과 같은 28px로 유지한다. - 레벨 열에서 행을 추가하거나 삭제할 때 레벨 열의 높이 변화에 맞춰 팔라딘 열도 동적으로 위아래로 이동해야 한다. - 팔라딘 열의 이동은 레벨 행의 펼침/접힘 애니메이션과 연동되어야 하며, 이동 중 간격이 갑자기 바뀌거나 팔라딘 열이 순간 이동하는 것처럼 보이지 않아야 한다. - 다른 category-column의 배치 순서와 기존 행 추가·삭제·드래그 기능은 변경하지 않는다. ## 6개 열의 슬라이드 탐색 UI ### 적용 범위 및 화면 구성 - 슬라이드 탐색은 `category-title`이 `내 정보`인 열부터 `전투 스킬(패시브)`인 열까지의 6개 열에 적용한다. - 기존 `레벨` 및 `팔라딘` 열의 배치와 동작은 유지한다. - 6개 열은 한 번에 한 열만 표시하며, 이미지 참고 디자인처럼 상단 중앙에 페이지 점 6개, 테이블 좌우에 이전/다음 화살표를 배치한다. - 기존 category-card의 제목, 행, 테마, 입력 영역과 행 추가·삭제 기능을 유지한다. 위치 데이터 및 입력값을 새로 만들거나 초기화하지 않는다. ### 화살표 클릭 - 좌우 화살표의 클릭 반응 영역은 아이콘 자체보다 넓게 확보한다. - 왼쪽 화살표는 이전 열로, 오른쪽 화살표는 다음 열로 정확히 한 열씩 이동한다. - 첫 번째 열인 `내 정보`에서는 왼쪽 화살표를 숨기고 동작하지 않게 한다. - 마지막 열인 `전투 스킬(패시브)`에서는 오른쪽 화살표를 숨기고 동작하지 않게 한다. - 이동은 부드러운 슬라이드 애니메이션으로 표시한다. ### 슬라이드/드래그 - 화살표의 클릭 영역을 제외한 슬라이드 뷰포트 영역에서는 마우스 드래그 및 터치 슬라이드로 좌우 이동할 수 있다. - 좌우 이동 거리가 최소 임계값 이상이고 수직 이동보다 수평 이동이 뚜렷할 때만 열을 변경한다. 임계값 미만이면 현재 열을 유지한다. - 텍스트 입력, 값 입력, 선택 목록, 버튼 등 상호작용 요소에서 시작한 포인터 동작은 열 슬라이드로 처리하지 않는다. 입력·선택 조작 중 실수로 열이 바뀌지 않도록 한다. - 드래그/슬라이드 이동도 화살표와 동일하게 한 번에 한 열만 이동한다. - 터치 취소 등으로 제스처가 중단되면 열 이동을 수행하지 않는다. ### 페이지 점 - 페이지 점은 6개이며 각각 위치 ID 3000~8000의 열을 순서대로 나타낸다. - 현재 열에 대응하는 점은 내부를 채우고, 나머지 점은 내부를 비운 상태로 표시한다. - 현재 열이 아닌 점을 누르면 대응하는 열로 바로 이동한다. 현재 열의 점을 누르면 불필요한 이동을 수행하지 않는다. - 점 내부 채움색과 테두리색은 transition으로 부드럽게 변경한다. ### 애니메이션 시간 - 화살표와 슬라이드의 한 열 이동은 동일한 기본 전환 시간을 사용한다. - 페이지 점을 눌러 여러 열을 이동할 때는 목표 열까지의 거리와 관계없이 전체 애니메이션 시간이 일정해야 한다. 따라서 이동 열 수에 비례하여 이동 속도를 높이고, 중간 열마다 멈추지 않고 목표 열까지 연속 이동한다. - 시스템의 동작 감소 설정이 활성화된 경우 열 전환 및 점 상태 애니메이션을 생략한다. ### 검증 항목 - 6개 열의 순서와 페이지 점의 대응이 일치하는지 확인한다. - 첫 번째/마지막 열에서 해당 방향 화살표가 표시되지 않고 이동할 수 없는지 확인한다. - 화살표 클릭, 마우스 드래그, 터치 슬라이드, 페이지 점 클릭이 서로 충돌하지 않는지 확인한다. - 입력 필드나 선택 목록을 조작할 때 열이 바뀌지 않는지 확인한다. - 한 열 이동과 여러 열 이동의 전체 전환 시간이 동일한지 확인한다. - 기존 입력값, 행 추가·삭제 애니메이션, 추가 행 드래그 기능 및 레벨-팔라딘 배치를 확인한다. ## 슬라이드 탐색 UI의 위치 및 그림자 여백 - `.column-carousel` 전체를 기존 위치에서 오른쪽으로 약 100px 이동한다. 이전 화살표가 `.level-paladin-stack` 영역을 침범하거나 그 위에 겹치지 않아야 한다. - `.carousel-column`의 category-column 그림자 음영이 뷰포트 경계에서 잘리지 않도록 슬라이드 뷰포트 주변에 충분한 여백을 확보한다. 여백은 상하좌우 최소 24px를 기준으로 한다. - 각 `.carousel-column` 사이의 가로 간격은 약 40px로 유지한다. 열 이동 거리 계산에도 이 간격을 포함하여 페이지 점이나 화살표 이동 시 열이 정확히 뷰포트 중앙에 맞아야 한다. - 그림자 여백을 확보하더라도 뷰포트 외부의 다음/이전 열이 현재 열과 함께 노출되지 않도록 한다. - 검증 시 레벨-팔라딘 영역과 이전 화살표가 겹치지 않는지, 카드의 그림자 윤곽이 네 방향 모두 온전히 표시되는지, 열 간격이 일정한지 확인한다. ## 슬라이드 열의 너비 및 이동 정렬 보정 - 슬라이드 열 이동량은 뷰포트 너비를 열의 너비로 간주해 계산하지 않는다. 대상 `.carousel-column`의 실제 레이아웃 위치를 기준으로 이동하여 패딩이나 열 간격이 바뀌어도 페이지 점·화살표·스와이프 이동 위치가 정확히 일치해야 한다. - `.carousel-column`의 실제 카드 너비는 내부 `.input-row`의 전체 너비와 일치해야 한다. 설명 열, 적용 열, 값 입력 열의 너비 합계와 테두리를 기준으로 너비를 지정하고, 열 래퍼의 패딩 때문에 카드 내용이 좁아지거나 입력 행과 좌우 끝이 어긋나지 않도록 한다. - 그림자 표시를 위한 여백과 표시 영역은 카드 너비를 변경하는 용도로 사용하지 않는다. 그림자 여백을 확보하면서도 현재 카드의 입력 행이 좌우로 잘리거나 인접 카드가 불필요하게 노출되지 않아야 한다. - 검증 시 모든 페이지 점으로 이동해 카드의 좌우 끝과 입력 행의 좌우 끝이 일치하는지, 카드 전체가 표시되는지, 이전·다음 열이 현재 열과 겹치거나 잘못 노출되지 않는지 확인한다.
