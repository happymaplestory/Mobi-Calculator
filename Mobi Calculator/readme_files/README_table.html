# table.html 요구사항 ## 역할 마비노기 모바일 계산기의 위치 기반 게임 데이터 입력 테이블을 표시합니다. 데이터 분류는 `pages_js/data-model.js`에서 관리하고, 화면 생성은 `pages_js/table.js`, 시각적 표현은 `pages_css/table.css`에서 관리합니다. ## 화면 구성 - 위치 Table의 각 항목을 하나의 category-column으로 표시합니다. - category-column은 위치 ID 오름차순으로 배치합니다. - 각 category-column의 제목은 위치 Table의 `name` 값을 사용합니다. - 각 category-group에는 위치 항목이 참조하는 속성 그룹에 속한 구분 Table 항목을 행으로 표시합니다. - 속성 Table의 `name` 값은 화면에 표시하지 않습니다. - 기본 행은 첫 번째 열에 구분 Table의 `name`, 두 번째 열에 `+`, 세 번째 열에 사용자 입력 영역을 배치합니다. - 기본 행의 두 번째 열은 구분 Table의 적용 형식과 관계없이 `+`로 고정합니다. - ID 7000과 8000은 별도 지시가 있을 때까지 제목만 표시하며, 행 추가 기능도 표시하지 않습니다. - ID 1000~6000의 각 테이블 하단에는 행 추가 버튼을 표시합니다. - 행 추가 버튼을 누르면 새 행이 갑자기 나타나지 않고, 행이 부드럽게 펼쳐지면서 하단의 `+` 버튼도 함께 아래로 이동해야 합니다. - 새 행의 X 삭제 버튼도 행이 펼쳐지는 흐름에 맞춰 자연스럽게 페이드인해야 합니다. - 추가 행에는 구분 이름 텍스트 입력, 적용 형식 선택 목록, 값 텍스트 입력, 행 삭제 버튼을 표시합니다. - 추가 행의 적용 형식 선택 목록은 적용 Table의 모든 항목을 이름으로 표시하며, 선택값은 적용 항목 ID를 사용합니다. - 추가 행의 삭제 버튼을 누르면 오른쪽 입력값이 비어 있지 않을 때만 "(오른쪽 입력값 내용) 삭제하시겠습니까?"라는 확인 메시지를 표시합니다. 확인하면 해당 행을 삭제하고, 취소하면 행과 모든 입력값을 그대로 유지합니다. 오른쪽 입력값이 비어 있으면 확인 메시지 없이 즉시 삭제합니다. 삭제 버튼은 행 높이를 기준으로 세로 중앙에 정렬합니다. - 기존 행은 이동할 수 없으며, 사용자가 추가한 행만 드래그할 수 있습니다. 별도의 드래그 핸들 없이 추가 행의 어느 영역에서든 드래그를 시작할 수 있습니다. - 행은 마우스로 끌어 같은 위치 안에서 순서를 변경할 수 있습니다. 드래그 중 원본 행은 흐리게 표시하고, 이동 위치에는 placeholder를 표시하며, 드래그 중인 행은 포인터를 따라 표시합니다. placeholder 위치가 바뀔 때 주변 추가 행은 부드럽게 밀려나는 애니메이션을 표시합니다. - 추가 행끼리만 드래그로 순서를 변경할 수 있으며, 기본 행은 이동할 수 없습니다. - 같은 위치에서 순서를 변경하면 구분 이름, 적용 형식, 오른쪽 값 입력을 모두 유지합니다. - 다른 위치로 행을 이동할 때는 "입력 값만 이동됩니다."라는 확인 메시지를 표시합니다. - 다른 위치로 이동을 확인하면 오른쪽 값 입력만 유지하고, 구분 이름 입력과 적용 형식 선택은 초기화한 뒤 대상 위치로 이동합니다. - 다른 위치로 이동을 취소하면 원래 위치와 구분 이름, 적용 형식, 오른쪽 값 입력을 모두 유지합니다. - 유효한 대상 위치가 아닌 곳에서 드래그를 끝내면 원래 위치와 모든 입력값을 복원합니다. - 포인터 입력이 취소되는 등 드래그가 중단되어도 원본 행과 입력값을 보존하고, 드래그용 복제 행·placeholder·대상 강조 상태를 정리합니다. - 화면 너비가 바뀌어도 category-column의 배치 순서와 열 구성을 자동으로 재계산하지 않습니다. 좁은 화면에서는 가로 스크롤로 확인합니다. ## 입력 영역 - 값 입력은 숫자뿐 아니라 `%` 및 필요한 텍스트를 입력할 수 있도록 `input type="text"`를 사용합니다. - 추가 행의 구분 이름은 텍스트로 직접 입력할 수 있어야 합니다. - 추가 행의 적용 형식은 선택 목록에서 고를 수 있어야 합니다. - 입력값과 구분 이름은 텍스트 선택 및 복사가 가능해야 합니다. ## 테마와 hover - 행 hover 배경색은 단일 회색이 아니라 해당 category-card의 제목 색상과 어울리는 색상 계열을 사용합니다. - 추가 및 삭제 버튼의 테두리와 hover 색상은 해당 category-card 테마를 따릅니다. ## 데이터 참조 규칙 - `table.js`는 `data-model.js`의 `MOBI_DATA_MODEL`을 참조합니다. - 위치 항목은 `locationTable`의 ID, 이름, `attributeGroups`를 사용합니다. - 구분 항목은 `sectionTable`의 `id`, `group`, `name`을 사용합니다. - 행은 위치 항목이 참조하는 속성 그룹에 해당하는 구분 항목을 모아 구분 ID 오름차순으로 표시합니다. - 추가 행의 적용 목록은 `applicationTable`에서 생성합니다. - 입력값을 계산에 사용하거나 JSON으로 저장하는 기능은 이 변경에 포함되지 않습니다. ## 관련 파일 - `table.html`: 데이터 모델과 화면 스크립트 연결 - `pages_js/data-model.js`: 위치·속성·구분·적용 데이터 정의 - `pages_js/table.js`: 위치별 열과 행 생성 및 추가/삭제 동작 - `pages_css/table.css`: 레이아웃 및 시각적 표현 ## 행 삭제 애니메이션 - 삭제가 확정되면 해당 행이 즉시 사라지지 않고 높이와 투명도가 줄어들며 접힌다. - 삭제 행이 접히는 동안 아래쪽 행과 하단의 `+` 버튼은 문서 흐름에 따라 위로 이동하여 빈 공간을 덮는다. - 삭제되는 행의 X 버튼도 행이 접히는 동안 자연스럽게 페이드아웃해야 한다. - 입력값이 있을 때 표시하는 기존 삭제 확인창과 취소 동작을 유지한다. 입력값이 비어 있으면 확인창 없이 애니메이션 후 삭제한다. - 시스템의 동작 감소 설정이 활성화되어 있으면 애니메이션을 생략한다. ## 레벨 및 팔라딘 열 배치와 연동 애니메이션 - `category-title`이 `레벨`인 `category-column` 바로 아래에 `category-title`이 `팔라딘`인 `category-column`을 세로로 배치한다. 팔라딘 열은 다른 열과 나란히 배치하지 않는다. - 레벨과 팔라딘 열은 하나의 세로 스택으로 묶고, 두 열 사이 간격은 기존 열 사이 간격과 같은 28px로 유지한다. - 레벨 열에서 행을 추가하거나 삭제할 때 레벨 열의 높이 변화에 맞춰 팔라딘 열도 동적으로 위아래로 이동해야 한다. - 팔라딘 열의 이동은 레벨 행의 펼침/접힘 애니메이션과 연동되어야 하며, 이동 중 간격이 갑자기 바뀌거나 팔라딘 열이 순간 이동하는 것처럼 보이지 않아야 한다. - 다른 category-column의 배치 순서와 기존 행 추가·삭제·드래그 기능은 변경하지 않는다. ## 6개 열의 슬라이드 탐색 UI ### 적용 범위 및 화면 구성 - 슬라이드 탐색은 `category-title`이 `내 정보`인 열부터 `전투 스킬(패시브)`인 열까지의 6개 열에 적용한다. - 기존 `레벨` 및 `팔라딘` 열의 배치와 동작은 유지한다. - 6개 열은 한 번에 한 열만 표시하며, 이미지 참고 디자인처럼 상단 중앙에 페이지 점 6개, 테이블 좌우에 이전/다음 화살표를 배치한다. - 기존 category-card의 제목, 행, 테마, 입력 영역과 행 추가·삭제 기능을 유지한다. 위치 데이터 및 입력값을 새로 만들거나 초기화하지 않는다. ### 화살표 클릭 - 좌우 화살표의 클릭 반응 영역은 아이콘 자체보다 넓게 확보한다. - 왼쪽 화살표는 이전 열로, 오른쪽 화살표는 다음 열로 정확히 한 열씩 이동한다. - 첫 번째 열인 `내 정보`에서는 왼쪽 화살표를 숨기고 동작하지 않게 한다. - 마지막 열인 `전투 스킬(패시브)`에서는 오른쪽 화살표를 숨기고 동작하지 않게 한다. - 이동은 부드러운 슬라이드 애니메이션으로 표시한다. ### 슬라이드/드래그 - 화살표의 클릭 영역을 제외한 슬라이드 뷰포트 영역에서는 마우스 드래그 및 터치 슬라이드로 좌우 이동할 수 있다. - 좌우 이동 거리가 최소 임계값 이상이고 수직 이동보다 수평 이동이 뚜렷할 때만 열을 변경한다. 임계값 미만이면 현재 열을 유지한다. - 텍스트 입력, 값 입력, 선택 목록, 버튼 등 상호작용 요소에서 시작한 포인터 동작은 열 슬라이드로 처리하지 않는다. 입력·선택 조작 중 실수로 열이 바뀌지 않도록 한다. - 드래그/슬라이드 이동도 화살표와 동일하게 한 번에 한 열만 이동한다. - 터치 취소 등으로 제스처가 중단되면 열 이동을 수행하지 않는다. ### 페이지 점 - 페이지 점은 6개이며 각각 위치 ID 3000~8000의 열을 순서대로 나타낸다. - 현재 열에 대응하는 점은 내부를 채우고, 나머지 점은 내부를 비운 상태로 표시한다. - 현재 열이 아닌 점을 누르면 대응하는 열로 바로 이동한다. 현재 열의 점을 누르면 불필요한 이동을 수행하지 않는다. - 점 내부 채움색과 테두리색은 transition으로 부드럽게 변경한다. ### 애니메이션 시간 - 화살표와 슬라이드의 한 열 이동은 동일한 기본 전환 시간을 사용한다. - 페이지 점을 눌러 여러 열을 이동할 때는 목표 열까지의 거리와 관계없이 전체 애니메이션 시간이 일정해야 한다. 따라서 이동 열 수에 비례하여 이동 속도를 높이고, 중간 열마다 멈추지 않고 목표 열까지 연속 이동한다. - 시스템의 동작 감소 설정이 활성화된 경우 열 전환 및 점 상태 애니메이션을 생략한다. ### 검증 항목 - 6개 열의 순서와 페이지 점의 대응이 일치하는지 확인한다. - 첫 번째/마지막 열에서 해당 방향 화살표가 표시되지 않고 이동할 수 없는지 확인한다. - 화살표 클릭, 마우스 드래그, 터치 슬라이드, 페이지 점 클릭이 서로 충돌하지 않는지 확인한다. - 입력 필드나 선택 목록을 조작할 때 열이 바뀌지 않는지 확인한다. - 한 열 이동과 여러 열 이동의 전체 전환 시간이 동일한지 확인한다. - 기존 입력값, 행 추가·삭제 애니메이션, 추가 행 드래그 기능 및 레벨-팔라딘 배치를 확인한다. ## 슬라이드 탐색 UI의 위치 및 그림자 여백 - `.column-carousel` 전체를 기존 위치에서 오른쪽으로 약 50px 이동한다. 이전 화살표가 `.level-paladin-stack` 영역을 침범하거나 그 위에 겹치지 않아야 한다. - `.carousel-column`의 category-column 그림자 음영이 뷰포트 경계에서 잘리지 않도록 슬라이드 뷰포트 주변에 충분한 여백을 확보한다. 여백은 상하 15px, 좌우 24px를 기준으로 한다. 좌우 패딩은 15px로 조정한 경우에도 그림자 윤곽이 잘리지 않는지 확인한다. - 각 `.carousel-column` 사이의 가로 간격은 50px로 유지한다. 열 이동 거리 계산에도 이 간격을 포함하여 페이지 점이나 화살표 이동 시 열이 정확히 뷰포트 중앙에 맞아야 한다. - 그림자 여백을 확보하더라도 뷰포트 외부의 다음/이전 열이 현재 열과 함께 노출되지 않도록 한다. - 검증 시 레벨-팔라딘 영역과 이전 화살표가 겹치지 않는지, 카드의 그림자 윤곽이 네 방향 모두 온전히 표시되는지, 열 간격이 일정한지 확인한다. ## 슬라이드 열의 너비 및 이동 정렬 보정 - 슬라이드 열 이동량은 뷰포트 너비를 열의 너비로 간주해 계산하지 않는다. 대상 `.carousel-column`의 실제 레이아웃 위치를 기준으로 이동하여 패딩이나 열 간격이 바뀌어도 페이지 점·화살표·스와이프 이동 위치가 정확히 일치해야 한다. - `.carousel-column`의 실제 카드 너비는 내부 `.input-row`의 전체 너비와 일치해야 한다. 설명 열, 적용 열, 값 입력 열의 너비 합계와 테두리를 기준으로 너비를 지정하고, 열 래퍼의 패딩 때문에 카드 내용이 좁아지거나 입력 행과 좌우 끝이 어긋나지 않도록 한다. - 그림자 표시를 위한 여백과 표시 영역은 카드 너비를 변경하는 용도로 사용하지 않는다. 그림자 여백을 확보하면서도 현재 카드의 입력 행이 좌우로 잘리거나 인접 카드가 불필요하게 노출되지 않아야 한다. - 검증 시 모든 페이지 점으로 이동해 카드의 좌우 끝과 입력 행의 좌우 끝이 일치하는지, 카드 전체가 표시되는지, 이전·다음 열이 현재 열과 겹치거나 잘못 노출되지 않는지 확인한다. ## 슬라이드 탐색 간격 세부 조정 - `.column-carousel`의 왼쪽 여백은 50px로 설정한다. - `.column-carousel-viewport`의 좌우 패딩은 각각 15px로 설정한다. 상하 그림자 여백은 기존 24px를 유지한다. - 간격 조정 후 이전 화살표와 레벨·팔라딘 영역이 겹치지 않는지, 카드 그림자가 잘리지 않는지, 현재 열과 인접 열의 노출 및 정렬이 유지되는지 확인한다. ## 슬라이드 열 간격 추가 조정 - `.column-carousel-track` 내부 `.carousel-column` 사이의 `gap`은 기존 40px에서 10px 늘린 50px로 설정한다. - 페이지 점, 이전·다음 화살표, 스와이프 이동은 대상 열의 실제 레이아웃 위치를 기준으로 계산하여 늘어난 10px 간격이 이동 거리에 반영되어야 한다. 간격 조정 후 이동 위치가 어긋나거나 카드가 잘리고 인접 열이 불필요하게 노출되지 않는지 확인한다. ## 페이지네이션 클릭 영역 및 레벨·팔라딘 상단 간격 - `.column-pagination`에 `margin-bottom: 15px`를 적용해 페이지 점의 클릭 반응 영역이 `.column-carousel-viewport` 상단 패딩 영역과 겹쳐 비활성화되는 문제를 방지한다. 페이지 점 각각을 정상적으로 클릭할 수 있어야 한다. - `.level-paladin-stack`의 상단 margin은 기존 38px에서 20px 늘린 58px로 설정한다. - `.column-carousel`에는 상단 margin 20px를 추가한다. 두 요소의 기존 가로 배치 및 내부 간격은 유지한다. - 간격 조정 후 페이지 점 클릭과 열 이동이 정상 동작하는지, 레벨·팔라딘 영역의 배치 및 화살표와의 간격이 유지되는지 확인한다. ## 800x800 콘텐츠 박스 및 확대·축소 정렬 - `h1` 제목은 콘텐츠 박스 바깥에 유지하고, 그 외 본문 콘텐츠 요소는 `.table-content-box` 안에 배치한다. 스크립트 요소도 해당 래퍼 안에 둔다. - `.table-content-box`의 CSS 너비와 높이는 각각 800px로 고정한다. - 박스는 브라우저 뷰포트의 가로 중앙을 기준으로 배치한다. 페이지 확대·축소 또는 뷰포트 너비 변경 시 왼쪽이나 오른쪽으로 치우치지 않도록 뷰포트 기준 중앙 정렬을 유지한다. - 박스는 `h1` 제목 바로 아래에 배치하며, 세로 중앙 정렬이나 추가적인 상하 정렬을 적용하지 않는다. - 박스의 테두리는 표시하지 않는다. 박스의 CSS 너비와 높이는 각각 800px로 유지한다. - 박스 내부 콘텐츠가 세로 방향으로 800px 영역을 벗어나더라도 잘리지 않고 아래쪽으로 계속 표시되어야 한다. 가로 방향으로 넘치는 콘텐츠는 클립하고, 박스 자체의 가로·세로 스크롤바는 표시하지 않는다. - 슬라이드 탐색에서 다음·이전 열을 이동할 때 사용하는 내부 뷰포트의 클리핑은 유지하며, 박스 외부에 있는 요소나 이미지가 문서 전체의 가로 스크롤을 유발하지 않아야 한다. - `h1` 제목은 페이지 배경과 텍스트 색상에 어울리는 강조 스타일을 적용한다. 제목 아래에는 중앙 정렬된 가는 장식선을 배치하고, 제목은 콘텐츠 박스와 분리된 상태를 유지한다. - 기존 테이블 생성, 슬라이드 탐색, 행 추가·삭제·드래그 및 레벨·팔라딘 배치 기능은 유지한다. - 검증 시 100% 확대와 확대·축소 상태에서 박스의 CSS 크기가 800x800인지, 뷰포트 가로 중앙에 유지되는지, 박스가 제목 바로 아래에 있는지, 박스 내부와 페이지에 가로·세로 스크롤바가 나타나지 않는지 확인한다. ## 하단 장식 요소 제거 및 제목·열 배치 미세 조정 - `body::after`가 생성하던 페이지 하단 여백용 가상 요소를 제거한다. - `.table-area::after`가 생성하던 가로 구분선을 제거한다. - `column-pagination`은 기존 레이아웃 공간을 유지하면서 시각적 위치와 클릭 영역을 위로 15px 이동한다. - `h1` 제목 색상은 기존보다 조금 연한 회색(`#555555`)으로 표시한다. - `level-paladin-stack`의 왼쪽 category-column 그림자가 `.table-content-box`의 가로 클리핑 경계에 닿아 잘리지 않도록 스택에 왼쪽 여백을 확보한다. 레벨·팔라딘 열 사이 간격과 열 내부 구성을 변경하지 않는다. ## 페이지네이션 좌측 이동 및 콘텐츠 박스 위치·최소 너비 조정 - `h1` 제목의 하단 margin은 8px로 설정한다. 페이지네이션 상단 클릭 영역과 제목 영역의 겹침을 줄이기 위한 조정이며, 제목의 나머지 스타일은 유지한다. - `.column-pagination` 전체를 기존 위치에서 추가로 왼쪽 5px 이동한다. 따라서 기존의 `translateX(-5px)`를 `translateX(-10px)`로 조정하며, 위쪽 15px 이동은 유지한다. - 페이지 점의 실제 원형 표시 크기 22x22px와 점 사이 시각적 간격은 유지한다. 각 점 버튼의 클릭 영역은 34x34px로 넓혀 원 바깥에서도 선택할 수 있도록 하며, 이를 위해 투명한 버튼 영역 안에 기존 원형 표시를 별도 요소로 그린다. - `.table-content-box`는 뷰포트 가로 중앙 정렬 기준에서 오른쪽으로 20px 이동한다. 너비와 높이는 각각 800px로 유지한다. - `table.html` 페이지의 최소 가로 레이아웃 너비는 800px로 제한한다. 뷰포트가 800px보다 좁을 때도 문서 전체에 가로 스크롤바가 나타나지 않도록 가로 넘침은 클립한다. - 기존 테이블, 슬라이드 탐색, 행 추가·삭제·드래그 동작은 유지한다. ## 슬라이드 열 가장자리 안개 페이드 - `.column-carousel-viewport` 안에서 중앙의 주요 표시 영역은 불투명도를 100%로 유지해 열과 입력 UI가 온전히 보여야 한다. - 갑작스러운 경계 클리핑을 완화하기 위해 뷰포트 좌측 끝 20px, 우측 끝 28px 구간에 `mask-image` 선형 그라데이션을 적용한다. 각 가장자리에서는 투명하게 시작해 좌측은 안쪽 20px, 우측은 안쪽 28px 지점에서 완전히 표시되도록 한다. 좌측 페이드 범위는 기존 28px에서 8px 줄인다. - `-webkit-mask-image`도 함께 지정해 WebKit 기반 브라우저를 지원한다. - 마스크는 슬라이드 열이 들어 있는 `.column-carousel-viewport`에만 적용한다. 형제 요소인 `.level-paladin-stack`에는 마스크나 추가 클리핑을 적용하지 않아 레벨·팔라딘 열과 그림자가 가려지지 않아야 한다. - 기존 뷰포트의 `overflow: hidden`, 열 이동 거리, 50px 열 간격, 슬라이드 전환 및 입력 동작은 유지한다. ## 제목 너비 및 테마 버튼 사전 구성 - `h1` 제목의 너비는 500px로 설정하고 페이지 가로 중앙에 정렬한다. 좁은 뷰포트에서는 좌우 20px 여백을 넘지 않도록 최대 너비를 제한한다. - 테마 전환 버튼을 페이지 우측 상단에 고정 배치한다. 뷰포트의 위쪽과 오른쪽 가장자리에서 각각 20px 떨어져 있어야 하며, 페이지 길이와 본문 정렬의 영향을 받지 않아야 한다. - 버튼 크기는 50x50px로 고정하고, 기존 category-card와 유사한 테두리, 둥근 모서리, 배경 및 그림자 스타일을 사용한다. - 버튼 내부 아이콘과 다크/라이트 테마 전환 기능은 별도 지시가 있을 때 구현한다. 이 단계에서는 버튼의 위치와 외형만 구성하며 클릭 동작은 연결하지 않는다. ## 제목 및 테마 전환 버튼 아이콘 - `h1`은 margin을 통한 중앙 정렬을 사용하지 않는다. 가로 기준 중앙 배치는 `left: 50%` 및 `transform: translateX(-50%)`로 처리한다. - 테마 전환 버튼은 우측 상단에서 20px 간격을 유지하고 50x50px 크기로 표시한다. - 버튼 테두리는 이전보다 연한 색으로 표시하고, 버튼 배경은 body 배경색과 동일하게 한다. - 버튼 내부 아이콘은 24x24px 영역의 초승달 모양으로 구성한다. 색상은 탁하고 채도가 낮은, 연회색에 가까운 노란색을 사용한다. - 이번 단계에서는 아이콘 모양만 추가하며 실제 다크/라이트 모드 전환 동작은 구현하지 않는다. ## 제목 정렬 및 다크모드 버튼 hover 상태 - `h1`의 가로 중앙 정렬은 body의 최소 너비에 영향을 받지 않도록 `left: 50vw`와 `transform: translateX(-50%)`를 사용한다. 뷰포트 너비가 약 810px 이하로 줄어드는 경우에도 제목의 중심은 뷰포트 가로 중심과 일치해야 한다. - 기존 초승달 아이콘 버튼의 접근성 레이블과 툴팁은 `다크모드`로 정의한다. 이 변경은 버튼의 목적을 명확히 하며 실제 테마 전환 기능은 별도 지시 전까지 연결하지 않는다. -
